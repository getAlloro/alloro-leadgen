Why

The audit tool is the first thing many owners see of Alloro, and it does not look like Alloro. Its headings use a different font (Playfair Display, while alloro.com uses Spectral), its headline fades into an orange that is not in the palette, and its screens mix cold blue-greys, blue and orange grade boxes and navy panels into a warm terracotta brand. Small text (83 places at 9–11px) is hard to read, and on a phone three "Create account" buttons show at once while a sticky bar covers about 110px of the report. This plan gives it alloro.com's fonts, colours and calm motion, so the tool and the site read as one company, without changing what the tool does.

Metric line: no number moves by design. The test is "looks like alloro.com, works the same". Email capture is tracked by the tool already; this plan must leave those counts unchanged in kind (same events, same order).

Rules (Jov's words, made checkable)

  • "Save a copy so we can easily undo it." Done before any change. See Backup and undo.
  • "Make sure nothing breaks, and still works the same as before." Every slice re-runs the existing proof walk (report links, email card, unlock) and compares the list of requests the tool sends with today's list. Both must match before a slice is shown to Jov.
  • "Nothing added or removed. Only update the UI/UX part." No change to: what the tool asks, sends or stores; the order of screens; timings; tracking events; the email card's place (Jov's final verdict, 2026-10-13); words, except the one wording change Jov approved (Q3). Items from the list that would add or remove content without an explicit yes are held out (see Not in this plan).
  • "Don't overkill." Motion plays once, is short, and is off for anyone whose device asks for less motion.
  • Fonts and colours from alloro.com only. Plus Jakarta Sans and Spectral; alloro.com's tokens: terracotta #d66853, terracotta-text #b1462c, terracotta-deep #c0543a, ink #171615, ink-soft #3b3531, muted #6b635c, line #e8e4df, line-strong #d8d3cc, paper #f7f5f3, surface #ffffff, green #4f8a5b, amber #d9a441. The tool keeps its own beige page colour #fbf8f0.

How to undo

  1. One slice: revert that slice's merge commit on main (git revert -m 1 <merge sha>) and push. The deploy workflow rebuilds and copies the previous files to the server, as for any merge.
  2. Everything at once: push the tagged commit's tree back to main as a new commit (restore, not force-push), or revert every slice merge newest first.
  3. Last resort, without GitHub: copy live-site/index.html and live-site/assets/ into ~/audit on the server (needs the server login, which Dave holds).

Each slice is its own PR, so each is undone on its own. The deploy copies new files but never deletes old ones, so an undo serves the old bundle again by name.

Risk

  • Production on merge (Level 2). Mitigation: one slice per PR, each proved locally with screenshots for Jov first, merged only on his word, undone by one revert.
  • Turning on index.css changes more than motion (Level 2). It carries a Tailwind v4 import, a theme and a heading font rule that would land on top of the runtime Tailwind v3. Mitigation: S1–S5 do not link it; motion goes in a new small stylesheet bundled by Vite. S6 retires both the runtime CDN and the dead index.css in one change, proved by a pixel comparison.
  • Cherry-picking the scan screens (Level 2). The branch also carries a scan-walk timing change and email-card changes. Mitigation: take only the layout of GBPAnalysisStage / WebsiteScanStage; the request and timing checks (A2, A9) fail if anything else came along.
  • Colour swaps touch many files. Mitigation: colours change through a token map (one place), then class swaps file by file, and the words check (A3) and request check (A2) run on every slice.
  • Blast radius: the audit tool only. The main app, its API and alloro.com are not touched. The report email (sent by the backend) is not touched.
